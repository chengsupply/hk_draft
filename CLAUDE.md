## Запреты

Нарушение любого из них — не стилистический спор, а возврат работы.

- **Не выдумывать цифры и факты.** Ни количество брендов, ни сроки, ни
  отзывы, ни сертификаты, ни год основания. Цифра появляется на сайте
  только от клиента. Вся история этого правила — в PRODUCT.md.
- **Не добавлять формы.** Заявка идёт через почту и WeChat. Форм на сайте
  нет по решению, а не по недоделке. Бэкенда тоже нет — это статика.
- **Не возвращать телефон и WhatsApp.** Убраны намеренно.
- **Не придумывать имя, логотип, слоган.** Компания — Cheng Trading
  Limited, в шапке и подвале стоит знак CTL в двух цветовых версиях.
  Почта — `sales@chengsupply.com`, она настоящая: домен и ящик заведены
  23.10.2026. Второго адреса не выдумывать.
- **Не править вручную `site/src/styles/fonts.css`** в части `@font-face`.
  Файл генерируется скриптом.
- **Не класть файлы руками в `site/public/fonts/` и `site/public/images/`.**
  Это выход сборки. Оригиналы кладутся в `fonts-src/` и `images-src/`.

## Двуязычность

Английская `/` и 简体中文 `/zh-cn` равноправны.

- Все строки — в `site/src/i18n/dict.ts`, обе локали сразу.
- Заголовок героя впечатан в фотографию, поэтому у каждого языка свой
  комплект кадров. **Меняешь один — меняй второй**, кадр в кадр.
- Гонконгский адрес остаётся английским на обеих версиях: по нему ходит
  почта. Китайское написание не придумывать.

## Сборка ассетов

Оба скрипта ломаются молча: сайт соберётся, ошибки не будет, испортится
только результат. Прогонять из `site/`.

```bash
python3 scripts/build-fonts.py    # после правки текстов, особенно китайских
python3 scripts/build-images.py   # после добавления или замены картинок
```

Шрифты обрезаны до символов, которые есть в исходниках: новый иероглиф без
пересборки отрисуется системным шрифтом. Нужны `fonttools` и `brotli`.

## Домен, DNS и почта

Домен `chengsupply.com` куплен у UnderHost, но серверы имён указывают на
Cloudflare — у регистратора нет редактора записей. Сайт на GitHub Pages,
почта в Zoho (европейский дата-центр).

**DNS правится из терминала, в браузер ходить не надо.** Токен лежит в
`.env.local` в корне репозитория, он в git не едет и между машинами
переносится руками.

```bash
set -a && . ./.env.local && set +a
ZID=$(curl -sS "https://api.cloudflare.com/client/v4/zones?name=$CLOUDFLARE_ZONE_NAME" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" | python3 -c \
  "import sys,json; print(json.load(sys.stdin)['result'][0]['id'])")
curl -sS "https://api.cloudflare.com/client/v4/zones/$ZID/dns_records?per_page=100" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

Токен узкий: область — только зона `chengsupply.com`, право — только
`DNS:Edit`. Ни аккаунтом, ни другими зонами, ни почтой он не распоряжается.
Отзывается в Cloudflare → My Profile → API Tokens.

**Проксирование у всех записей выключено** («DNS only», серое облако). Под
оранжевым облаком GitHub Pages не выпустит сертификат, и сайт отдаст ошибку.
Новые записи для сайта заводить только с `"proxied": false`.

Репозиторий принадлежит аккаунту клиента `chengsupply`, и других участников
в нём нет. Поэтому обычный `gh`, настроенный на личную учётку, сюда не ходит —
и код, и настройки Pages идут по ключу клиента из того же `.env.local`:

```bash
set -a && . ./.env.local && set +a
curl -sS -H "Authorization: Bearer $GITHUB_CHENGSUPPLY_TOKEN" \
  -H "Accept: application/vnd.github+json" \
  https://api.github.com/repos/chengsupply/hk_draft/pages
```

Токен бессрочный, права: Administration, Contents, Pages, Workflows на запись,
Metadata на чтение. Отзывается на github.com/settings/personal-access-tokens.

## Разработка

```bash
cd site
npm install
npm run dev      # http://localhost:4321
npm run build && npm run preview
```

Пуш в `main` публикует сайт. Проверять сборку до пуша.

## Дизайн

DESIGN.md — источник правды. Что нарушается чаще всего:

- контент с острыми углами, интерфейс со скруглёнными;
- одна красная кнопка на экран, не две;
- золото — волосяная линия и надпись, заливка разрешена только под
  заголовком секции;
- тень только у того, что «плавает» над страницей.
