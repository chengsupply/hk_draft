# Решения проекта — HK

Файл создан 05.10.2026 при анализе проекта. Ниже перенесены действующие
решения из PRODUCT.md и DESIGN.md; новых продуктовых решений не принято.

## 2026-10-23 — Домен chengsupply.com, DNS в Cloudflare, почта в Zoho

- **Решение:** домен куплен у UnderHost, но его серверы имён заменены на
  Cloudflare (`lynn` / `may.ns.cloudflare.com`); сайт остаётся на GitHub Pages,
  почта — Zoho Mail в европейском дата-центре.
- **Почему:** у UnderHost нет редактора DNS-записей вообще — без него нельзя
  добавить ни A/AAAA для Pages, ни MX для почты. Cloudflare бесплатен и даёт
  полноценный редактор.
- **Отвергли и почему:** оставить DNS у регистратора — невозможно, записей
  негде завести. Перенести сайт на хостинг UnderHost — отказались, сборка уже
  едет через GitHub Actions и ничего не стоит. Cloudflare Email Routing —
  он только пересылает входящие, отправлять с адреса домена нельзя.
- **Цена:** ещё один сервис в цепочке; при смене регистратора серверы имён
  надо будет прописать заново.

## 2026-10-23 — Все записи в Cloudflare стоят «DNS only», без проксирования

- **Решение:** оранжевое облако выключено у всех записей, Cloudflare работает
  только как DNS.
- **Почему:** GitHub Pages сам выпускает сертификат Let's Encrypt и для этого
  должен видеть обращение напрямую. Под прокси Cloudflare проверка не проходит
  и сайт отдаёт ошибку сертификата.
- **Отвергли и почему:** включить прокси ради DDoS-защиты и кэша — Cloudflare
  предлагает это дважды при импорте и при активации, но для статики на Pages
  выигрыша нет, а сертификат ломается.
- **Цена:** нет кэша и защиты Cloudflare; IP-адреса GitHub видны в DNS.

## 2026-10-23 — sales@ — алиас, а не отдельный пользователь Zoho

- **Решение:** ящик один — `admin@chengsupply.com`; `sales@chengsupply.com`
  висит на нём алиасом и приходит в тот же почтовый ящик.
- **Почему:** работает один человек. Алиас бесплатен навсегда, отвечать с него
  Zoho позволяет.
- **Отвергли и почему:** заводить `sales@` отдельным пользователем — при
  переходе на платный тариф это вторая лицензия за те же письма.
- **Цена:** когда продажами займётся отдельный человек, алиас придётся
  превращать в пользователя и разделять переписку вручную.

## Статический сайт на Astro и GitHub Pages

- **Решение:** две языковые версии сайта-визитки, без серверной части.
- **Почему:** задача сайта — показать поставщика и перевести покупателя в прямое обращение; корзины, оплаты и публичных цен нет.
- **Отвергли и почему:** интернет-магазин и обработку заявок на сервере — они выходят за текущую задачу (PRODUCT.md, Capabilities and Constraints).
- **Цена:** обращения обрабатываются человеком вне сайта; доступность сайта из материкового Китая требует отдельной проверки.

## Связь только через почту и WeChat

- **Решение:** только два канала, без формы, телефона и WhatsApp.
- **Почему:** прямой разговор с покупателем, который уже имеет номер детали или перечень оборудования.
- **Отвергли и почему:** RFQ-форму, телефон и WhatsApp — от них намеренно отказались; настоящих телефонных данных не было (PRODUCT.md, решение 16.09.2026).
- **Цена:** оба разрешённых канала должны быть доступны на каждом размере экрана; без настоящей почты и проверенного WeChat путь обращения не завершён.

## Проверяемые сведения о компании

- **Решение:** реквизиты и коммерческие утверждения публикуются по данным клиента.
- **Почему:** закупщик проверяет реальность неизвестного поставщика.
- **Отвергли и почему:** выдуманные счётчики, сроки, отзывы и год основания — создают ложные основания для доверия (PRODUCT.md, Brand Commitments).
- **Цена:** неподтверждённые сведения остаются открытыми вопросами.

## Проектная визуальная система

- **Решение:** DESIGN.md фиксирует действующую систему; контентные карточки имеют острые углы, элементы управления могут иметь скругления и лёгкие тени. Золотая заливка разрешена у подписи секции.
- **Почему:** документ согласован с реализованным интерфейсом и просьбой клиента о золотых плашках.
- **Отвергли и почему:** исходный абсолютный запрет скруглений, теней и золотых заливок — не соответствовал принятому интерфейсу и указанному запросу клиента (DESIGN.md, Overview).
- **Цена:** исключения нужно соблюдать по роли элемента, а не применять ко всему сайту.
